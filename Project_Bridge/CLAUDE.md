## 1. 프로젝트 개요

- **산출물:** `bridge.html` — 단일 HTML 파일, 약 3,000라인.
- **단계:** 프로토타입.
- **주담당:** 메이데이(코딩 · 구조 보존). **검수:** 브릿지(고객 관점). 필요 시 도파민(UX · 표현).
- **작업 단위:** 한 번에 하나의 기능만. 기능은 가능한 한 작게 분할.
- (확인 필요) 앱의 기능 정의 · 화면 구성 · 사용 흐름은 인수인계 문서에 명시되어 있지 않음
  → `bridge.html` 실제 코드 확인 후 본 문서에 보강 필요.

---

## 2. 코드 고정 규칙 (위반 금지)

아래 8개는 예외 없이 지킵니다.

1. 변수 선언은 `var`만 사용한다. (`let` / `const` 금지)
2. 백틱(`` ` ``) 사용 금지. → 문자열은 작은따옴표/큰따옴표 사용.
3. HTML 템플릿 리터럴 `${ ... }` 금지.
4. 외부 라이브러리 · 프레임워크 금지. (순수 HTML / CSS / JS만)
5. 차트는 Canvas로 직접 구현한다. (차트 라이브러리 금지)
6. 전체 재작성 금지. 항상 **부분 수정만** 한다.
7. 기존 화면 흐름 · 네이밍 · localStorage 구조를 유지한다.
8. 코드를 출력할 때는 적용 위치(파일 내 함수 / 구간)를 반드시 명시한다.

## 3. 데이터 저장 구조 (localStorage)

- 저장은 **localStorage만** 사용한다. (외부 서버 · 클라우드 전송 없음)
- 고정 8개 키를 사용하며, 키 이름과 구조를 임의로 바꾸지 않는다.

| 키 | 용도 |
|----|------|
| `br_m` | members — 회원 데이터 **단일 원본(single source)** |
| `br_s` | (확인 필요) |
| `br_n` | (확인 필요) |
| `br_o` | (확인 필요) |
| `br_mb` | (확인 필요) |
| `br_tr` | (확인 필요) |
| `br_cfg` | (확인 필요) |
| `br_mat` | (확인 필요) |

- `br_m`은 회원 데이터의 단일 원본이므로, 회원 정보는 항상 `br_m`을 기준으로 읽고 쓴다. (사본 분기 금지)
- (확인 필요) `br_m` 외 7개 키의 정확한 용도는 인수인계 문서에 명시되어 있지 않음
  → `bridge.html` 코드 확인 후 채워야 하며, 명칭만으로 추정해 단정하지 않는다.

## 4. 앱 기능 범위 — 초기 개발 제외 항목

다음 기능은 초기 개발 범위에서 제외한다. 요청이 있어도 본 문서 갱신(사용자 확정) 전에는 구현하지 않는다.

- 로그인 기능
- 클라우드 저장
- 카카오톡 연동
- 구글드라이브 연동
- 개인정보 저장 기능 (기본적으로 만들지 않음)
- 외부 서버 전송 기능

---

## 5. 작업 방식

- 기능을 작게 나누고, 한 세션에서 **하나의 기능만** 구현하거나 정리한다.
- 기능 상태를 **완료 / 진행 중 / 보류**로 구분해 관리한다.
- **코드 수정 전:** 변경 목적을 먼저 기록한다.
- **코드 수정 후:** 변경한 파일과 이유를 기록한다.
- 같은 오류가 반복되면 무리하게 계속 수정하지 않고, 리포트로 정리해 멈춘다.
